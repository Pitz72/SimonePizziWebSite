# v1.19.0 — Security Hardening Completo (11 Giugno 2026)

Release dedicata interamente alla sicurezza: risolve tutte le criticità emerse
dall'audit completo dell'11/06/2026 (backend PHP, frontend React, igiene repo).
Verifica preliminare sul server: nessuno script residuo raggiungibile, nessun
backup esposto — i fix blindano il codice perché il rischio non si ripresenti.

## Backend PHP

### Critiche / Alte

- **backup.php** — i backup automatici ora vanno in una directory **fuori dalla
  document root** (`../db_backups_simonepizzi`, permessi 0700); in fallback usa
  `.data/backups` ma ricrea a runtime gli `.htaccess` di diniego (clean-dist.js
  elimina `.data/` dalla dist, quindi il deny del repo non arrivava mai sul
  server). Nome file con suffisso random non indovinabile + `chmod 0600` +
  rotazione automatica (ultimi 15 backup).
- **auth.php** — eliminato il **password reset poisoning**: il link di recovery
  è costruito dalla nuova costante `SITE_URL` (definita in db.php, override
  possibile da config.php), mai da `HTTP_HOST`. Stesso fix in subscribers.php
  e newsletter_send.php.
- **auth.php** — rate limiting su `request-recovery` (3/IP/15min, riusa
  login_attempts con chiave marcata `rec:`); ogni nuova richiesta invalida i
  token di reset precedenti; password minima 12 caratteri sul reset.

### Medie

- **auth_helper.php** — i flag del cookie di sessione (HttpOnly, Secure,
  SameSite=Strict) sono ora applicati in **ogni** endpoint, non solo in auth.php.
- **auth_helper.php** — nuova difesa CSRF: sui metodi mutativi autenticati
  l'header Origin/Referer (se presente) deve corrispondere a SITE_URL.
- **auth_helper.php** — il check session_version è ora **fail-closed**: errore
  DB ⇒ 401, non più accesso consentito.
- **subscribers.php** — rate limiting sull'iscrizione newsletter pubblica
  (3/IP/15min): blocca il mail-bombing verso terzi tramite il form.
- **upload.php** — il nome file generato non può più contenere punti intermedi
  (niente doppie estensioni tipo `shell.php.jpg`).
- **public/uploads/.htaccess** (nuovo) — esecuzione PHP disattivata nella
  directory upload; clean-dist.js lo include nella dist (unico file di uploads/).
- **.htaccess** — redirect 301 forzato HTTP→HTTPS + header HSTS (1 anno).

### Basse

- **settings.php** — cambio password: minimo 12 caratteri lato server e
  `session_version++` (invalida le altre sessioni, come già faceva il reset).
- **download.php** — vincolo `/uploads/` + realpath sul path dal DB (difesa in
  profondità, come media.php).
- **analytics.php** — rimossi gli ALTER TABLE a ogni richiesta; `article_id`
  validato contro gli articoli esistenti sul tracking pubblico.
- **reactions.php** — secondo rate limit basato sul solo IP (il voter_hash
  include lo User-Agent, controllato dal client).
- **optimize_db.php** — i messaggi PDO vanno in error_log, non nella risposta.

## Frontend

- **Dipendenze** — `react-router-dom` 7.13.1 → 7.17.0 (6 advisory risolti, tra
  cui open redirect e stored XSS nel prerender), `dompurify` → 3.4.9; rimosso
  `showdown` (mai usato, ReDoS senza fix); `sharp` spostato in devDependencies.
  `npm audit --omit=dev`: **0 vulnerabilità**.
- **SingleArticle.tsx** — sanitizzazione estratta in `sanitizeArticleHtml()`,
  hook DOMPurify in try/finally (un'eccezione non lascia più l'hook globale
  registrato); whitelist iframe ristretta ai soli path `/embed/` di
  youtube.com / youtube-nocookie.com.
- **SearchModal.tsx** — usa `API_URL` (la ricerca funziona anche in dev),
  AbortController nel cleanup (niente race sui risultati), check `res.ok`.
- **App.tsx** — nuovo `AdminErrorBoundary` sulle rotte `/admin` (niente più
  stack trace di react-router in caso di errore di un loader).
- **AdminLayout.tsx** — rimosso il checkSession duplicato (resta quello del
  loader); link "Vedi Sito Live" corretto da `#/` a `/`.
- **useFetchArticles.ts** — `hasMore` calcolato sull'array reale post-dedup
  (eliminata la closure stantia).
- **mappers.ts** — parsing tags difensivo (stringa/array/altro).
- **Settings.tsx** — minimo password client allineato a 12 caratteri.

## Note di deploy

1. Build dal repo principale e upload FTP della `dist/` come sempre.
2. La `dist/` ora contiene `uploads/.htaccess`: va caricato (non tocca i media).
3. Verificare che sul server `config.php` definisca `BACKUP_CRON_SECRET` con un
   valore robusto; opzionale `SITE_URL` (default già corretto).
4. Al primo backup automatico verrà creata `~/db_backups_simonepizzi/` fuori
   dalla document root.
